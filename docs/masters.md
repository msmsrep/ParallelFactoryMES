**左メニュー：管理 → マスタ管理**

画面上部のタブで、9種類のマスタを切り替えます。

<div class="warn">
<p><strong>登録の順番が重要です。</strong> 工程を先に登録しないと工順（BOP）が作れず、
工順がないと製造指図を工程展開できません。次の順番で進めてください。</p>
</div>

<div class="flow">
  <span>① 工程</span><em>→</em>
  <span>② 品目</span><em>→</em>
  <span>③ MBOM</span><em>→</em>
  <span>④ 工順（BOP）</span><em>→</em>
  <span>⑤ ロケーション</span><em>→</em>
  <span>⑥ 設備・治工具・検査項目・チェックリスト・スキル・ユーザー</span>
</div>

マスタの登録・編集ができるのは **システム管理者** と **生産管理担当者** です
（ユーザーとスキル紐付けはシステム管理者のみ）。

件数が多いときは、1件ずつ入力する代わりに [CSVでの一括登録](#csv) が使えます。

## ① 工程

**タブ：工程**

製造の工程（切削、組立、検査など）を登録します。

| 項目 | 説明 |
|---|---|
| 工程コード | 一意のコード。作業指示や工順で参照されます |
| 工程名 | 表示名 |
| 工程区分 | 内製／外注の区分 |

## ② 品目

**タブ：品目・MBOM・工順**

製品・半製品・部材をすべて「品目」として登録します。

| 項目 | 説明 |
|---|---|
| 品目コード | 一意のコード。**ロット番号の先頭にも使われます** |
| 品目名 | 表示名 |
| 単位 | 個、kg など |
| 品目区分 | 製品／半製品・中間品／部材 |
| 規格 | 任意の規格情報 |
| 標準不良率(%) | 製造指図を展開したときの予定材料をこの率ぶん割り増します（0〜99.99） |

登録済みの品目は一覧に表示され、**編集**で内容を変更、**無効化**で以後の選択肢から外せます
（過去の実績は残ります）。

## ③ MBOM（部品構成）  {#mbom}

品目一覧の行にある **MBOM・工順** ボタンを押すと、その品目の構成を編集できます。

<ol class="steps">
<li><strong>子品目</strong>（使用する部材）を選びます。</li>
<li><strong>必要数量</strong>を入力します。これは<strong>親1単位あたり</strong>の数量です。</li>
<li><strong>内外製区分</strong>と、必要なら<strong>代替部品グループ</strong>を指定します。</li>
<li><strong>消費工程</strong>で、その部材を使う工程（工順の工程順序）を選びます。選ばなければ最終工程で使う扱いになります。</li>
<li><strong>明細に追加</strong>を押して行を積み上げます。</li>
<li>すべて追加したら <strong>MBOMを保存（一括置換）</strong> を押します。</li>
</ol>

<div class="warn">
<p>保存は<strong>一括置換</strong>です。画面に表示されている明細で既存の構成が丸ごと置き換わります。
1行だけ足したい場合も、既存行を残したまま追加して保存してください。</p>
<p>品目自身を子品目にすることはできません。構成が一周する登録（例：製品の子に半製品、半製品の子に製品）もできません。エラーには一周する経路が表示されます。</p>
<p>代替部品グループには、<strong>主材料（代替部品にチェックしない行）をちょうど1つ</strong>入れ、残りを代替部品にします。代替部品にチェックした行にはグループ名が必要です。</p>
</div>

MBOMは、実績入力の**バックフラッシュ**（部材の自動消費）で使われます。
バックフラッシュを使う予定があれば必ず登録してください。
製造指図を展開すると、MBOMから予定材料が作られます。予定数量は **必要数量 × 指図数量 ÷ (1 − 標準不良率)** です。
不良になる分も部材を使うため、親品目の標準不良率ぶん多めに見込みます（例：必要数量2・指図数量10・標準不良率20%なら予定数量25）。
バックフラッシュは各部材を**消費工程の作業指示でだけ**引くので、組立の工程で使う部材は消費工程に組立の工程を選んでください。

<div class="warn">
<p>消費工程に工順に無い工程順序を選んだままだと、製造指図を展開できません。工順を組み直したときはMBOMの消費工程も見直してください（一覧に「（工順に無し）」と表示されます）。</p>
</div>

## ④ 工順（BOP）  {#bop}

同じく品目一覧の **MBOM・工順** から編集します。**製造指図の工程展開にはこの工順が必須です。**

| 項目 | 説明 |
|---|---|
| 工程順序 | 実行順を表す数値。小さい順に作業指示が生成されます |
| 工程 | 登録済みの工程から選択 |
| 標準作業時間(分) / 標準段取り時間(分) | 参考値 |
| 必要スキル・資格 | 差立時に作業者の資格を照合します |
| 使用設備 / 使用治工具 | 既定の設備・治工具 |
| チェックリスト | この工程で実施するチェックリスト |
| 工程管理項目 | この工程で記録する製造条件（温度・回転数など）を、工程管理項目マスタから複数選択します。展開した作業指示に指示値と許容範囲が写り、実績と照合されます |
| 工程管理項目の補足 | 指示値の無い確認事項などのメモ |

**工程を追加** で行を積み上げ、**工順を保存（一括置換）** で確定します。MBOMと同様に一括置換です。

<div class="note">
<p><strong>最後の工程が「最終工程」</strong>として扱われます。最終工程の実績入力では入庫先ロケーションの
指定が必須になり、そこで製品ロットが在庫計上されます。</p>
</div>

## ⑧ 検査項目・基準  {#inspection-items}

**タブ：検査項目・基準**

検査指示を発行したとき、**対象の検査種別・品目・工程に合致する検査項目が自動的に選ばれます**。
つまりここに登録がないと検査指示を発行できません。

| 項目 | 説明 |
|---|---|
| 検査項目コード / 名称 | 基本情報 |
| 検査種別 | 受入検査／工程内検査／完成品検査／サンプル検査 |
| 対象品目 / 対象工程 | 適用範囲。指定した方は一致が必要で、両方指定すると「その品目のその工程」だけに使われます。未指定の方は問いません。対象工程を指定できるのは工程内検査だけで、受入・完成品・サンプル検査は対象品目が必須です |
| 規格値 下限 / 上限 | 測定値の合否をこの範囲で自動判定します |
| 基準値 | 目標値（表示用） |
| 検査方法 | 目視、ノギスなどの記述 |
| サンプリング数 | 判定に必要な最低サンプル数。この数だけサンプル番号の違う実績がそろうまで総合判定できません（多く測るのは構いません） |
| 必要スキル・資格 | 検査に資格が要る項目で指定します。検査実績を登録する人がその資格を持っていないか、期限が切れているとエラーになります（CSVでは `RequiredSkillCode` 列） |

<div class="note">
<p>上限・下限のどちらも設定していない項目は<strong>自動判定できません</strong>。
その項目は検査実績の入力時に、合否を手動で選ぶ必要があります。</p>
</div>

## CSVでの一括登録・出力  {#csv}

各タブの **CSV入出力** を開くと、マスタをCSVファイルでまとめて登録・出力できます。
初期導入で件数が多いときや、Excelでまとめて見直したいときに使ってください。

| ボタン | 内容 |
|---|---|
| CSVエクスポート | 登録済みの内容をCSVで出力（無効なものも含む） |
| テンプレート（空のCSV） | 列名だけのCSVを出力。新規登録用のひな形 |
| 取込を実行 | 選択したCSVファイルを取り込む |

対応しているのは、品目・MBOM・工順（BOP）・工程・設備・治工具・ロケーション・
検査項目・基準・チェックリスト・スキル・資格・ユーザー・ユーザーのスキル資格です。

**取込に必要な権限は、そのタブのフォームと同じです。**
スキル・資格・ユーザー・ユーザーのスキル資格の取込はシステム管理者のみで、
それ以外はマスタ管理の権限（システム管理者・生産管理担当者）が必要です。
権限がない場合、取込の欄そのものが表示されません（エクスポートは誰でも使えます。
ユーザー系のCSVは出力も管理者のみです）。

### サンプルCSV

書き方の見本として、そのまま取り込める**サンプルデータ一式**を用意しています。
ギアポンプを生産する小規模な工場を想定した内容で、ファイル名の番号順に取り込むと、
製造指図から出荷まで一通り試せる状態になります。

**[samples-master-csv.zip](https://github.com/msmsrep/ParallelFactoryMES/releases/latest/download/samples-master-csv.zip)**
（作業区・工程・ロケーション・品目・スキル・勤務シフト・設備・保全部品・治工具・チェックリスト・不良理由・検査項目・工程管理項目・検査機・MBOM・作業手順書・工順・ユーザー・保全手順書）。
下の「ZIPでまとめて取り込む」にそのまま渡せます。中身のCSVは [samples/master-csv](https://github.com/msmsrep/ParallelFactoryMES/tree/main/samples/master-csv) でも見られます。

まずはこのサンプルを取り込んで動きを確認し、エクスポートしたCSVを自社の内容に
書き換えて使うのが分かりやすい進め方です。

### ZIPでまとめて取り込む・出力する

マスタ管理画面の上にある **ZIPで一括取込・一括出力** を使うと、複数のCSVを1回で取り込めます。

- CSVをZIPにまとめて選びます。**ファイル名の順に取り込み**、種別はファイル名の「_」より後ろで決まります
  （`01_work-centers.csv` → 作業区）。サンプルの `samples-master-csv.zip` はそのまま取り込めます。
- **1ファイルでもエラーがあると、ZIPの全ファイルが取り消されます。** 結果にはファイルごとのエラーと、処理しなかったファイルが出ます。
- ZIPに入っている**全部の種別を取り込める権限**が必要です（例：ユーザーのCSVが入っていると、システム管理者以外は取り込めません）。
- 実績のCSVは入れられません。実績は **実績CSV取込** 画面でZIPにして取り込みます。
- 生産計画もマスタではないので入れられません。生産計画は **生産計画・予実** 画面の計画登録タブから取り込みます（[生産管理](production.html#plan)）。
- **全マスタをZIPで出力** すると、取り込む順の番号付きのCSVがまとめて出力されます。そのまま別の環境へ一括取込できます
  （ユーザーはパスワードを出力しないので、新しい環境で使うときはユーザーのCSVに `InitialPassword` を書き足してください）。

### 取込のきまり

- **コードが既存と一致すれば更新、無ければ新規登録**です（品目コード、工程コードなど）。
  設備は資産番号、ユーザーはユーザー名がキーになります。
- **列の順序は自由**です。不要な列は削除できます（削除した列は現在の値をそのまま保ちます）。
  逆に、列を残して**空欄にすると、その項目は空になります**。
- 文字コードは **UTF-8 / Shift_JIS のどちらでも取り込めます**（Excelの「CSV（カンマ区切り）」で保存したファイルもそのまま使えます）。
- 区分（品目区分・工程区分など）は `Product` のような英語の値のほか、画面と同じ **日本語（製品・部材 など）でも指定できます**。
- 有効／無効は `true` / `false`（`1` / `0`、`有効` / `無効` も可）。

<div class="warn">
<p><strong>1行でもエラーがあると、全件が取り消されます。</strong>
エラーは「何行目の何が悪いか」の一覧で表示されるので、CSVを直して取り込み直してください。
一部だけ登録される、ということはありません。</p>
<p><strong>検証のみ</strong> にチェックを入れて取り込むと、DBに反映せずエラーの有無だけを確認できます。
本番データに入れる前の確認に使ってください。</p>
</div>

### MBOM・工順・チェックリストの一括登録

明細を持つマスタは、**同じキーの行をまとめて1件**として扱い、**その明細を丸ごと置き換えます**。

- **MBOM**：`ParentProductCode`（親品目コード）が同じ行が、その親のMBOMになります。
  `RoutingSequence` に部材を使う工程の工程順序を書きます（空なら最終工程）。代替部品グループのルールと循環の禁止は、画面から登録したときと同じです。
- **工順**：`ProductCode`（品目コード）が同じ行が、その品目の工順になります。
- **チェックリスト**：`Code` が同じ行が、1つのチェックリストの項目になります。

CSVに登場しなかった親品目のMBOM・工順は変更されません。

<div class="note">
<p>MBOM・工順・検査項目のCSVは、品目コード・工程コードなどで他のマスタを参照します。
<strong>先に品目・工程などを登録してから</strong>取り込んでください（未登録のコードはエラーになります）。</p>
</div>

## 実績のCSV取込 {#actual-csv}

試験・移行・教育用に、**実績（受入・製造指図・段取り・チェックリスト・部材投入・生産実績・製造条件・検査・作業時間・トラブル報告・設備稼働記録・出荷指示・出荷判定・出荷実行・保全計画・保全指示・保全実績・治工具の利用実績と引当・検査機の校正・在庫オペレーション・搬送・ピッキング・棚卸・不適合・サンプル品保管）もCSVでまとめて登録できます**。
メニューの **管理 → 実績CSV取込** を開き、種別ごとのパネルから取り込みます。

- 1件ずつ画面から登録したときと**同じチェック**を通ります（校正期限切れの検査機、理由の無い代替部品の投入、在庫不足などは取り込めません）。
  在庫・ロットの状態・監査ログも同じように記録されます。
- **取込は常に新規登録**です。同じファイルを2回取り込むと、2回分の実績になります。
- 作業指示は **指図番号＋工程順序** で、投入・検査・出荷するロットは **ロット番号** で、出荷指示は **出荷番号** で、保全指示は **保全指示番号** で、棚卸は **棚卸番号** で、不適合は **不適合番号** か **ロット番号**（そのロットの未完了の不適合が1件だけのとき）で指します。
  製造指図の指図番号、後で投入するロットのロット番号、出荷指示の出荷番号、保全指示の保全指示番号、ピッキング・棚卸の番号は、CSVで指定しておいてください（自動採番の番号は取り込むまで分かりません）。
- **記録者は取り込んだユーザー**です。作業者を指定する列はありません。
- 取り込める権限は、種別ごとに画面から登録するときと同じです（受入・出荷指示・出荷実行は物流、製造指図は生産管理、検査は品質管理、出荷判定は品質保証 など。保全の突発依頼と実績・治工具の利用実績は誰でも、保全計画と計画保全の指示は保全担当者だけ、治工具の引当は生産管理、検査機の校正は品質管理）。
- 「1行でもエラーがあると全件取り消し」「検証のみ」はマスタのCSVと同じです。
- 画面の上の **ZIPで一括取込** で、複数のCSVを1回で取り込めます（ファイル名の順。1ファイルでもエラーがあればZIPの全ファイルを取り消し）。

受入から出荷まで一通りそろった**サンプル**が
**[samples-actual-csv.zip](https://github.com/msmsrep/ParallelFactoryMES/releases/latest/download/samples-actual-csv.zip)** にあります
（中身は [samples/actual-csv](https://github.com/msmsrep/ParallelFactoryMES/tree/main/samples/actual-csv)）。
[サンプルCSV](#サンプルcsv) のマスタを取り込んだ後に、ファイル名の番号順に取り込んでください。

ダッシュボードの週次・月次の推移や、工程・直・ライン・設備別の内訳を試すための**約3か月分の実績**は
**[samples-actual-csv-bulk.zip](https://github.com/msmsrep/ParallelFactoryMES/releases/latest/download/samples-actual-csv-bulk.zip)** にあります
（中身と見どころは [samples/actual-csv-bulk](https://github.com/msmsrep/ParallelFactoryMES/tree/main/samples/actual-csv-bulk)）。
期間は 2026-06-29〜2026-09-20 なので、ダッシュボードでは基準日をその期間に合わせて見てください。
同じ期間の生産計画のサンプル（[samples-production-plans.csv](https://github.com/msmsrep/ParallelFactoryMES/releases/latest/download/samples-production-plans.csv)）もあります（[生産管理](production.html#plan)を参照）。

### ユーザーのCSV（システム管理者のみ）

- 新規ユーザーには `InitialPassword`（初期パスワード。8文字以上、英小文字と数字を含む）が必要です。
  初回ログイン時にパスワード変更を求められます。
- `Roles` はセミコロン区切りです（例：`Operator;QualityControl`）。
- 既存ユーザーの行で `InitialPassword` を書くと**パスワードのリセット**になります。空欄なら変更されません。
- `IsActive` を `false` にすると無効化され、そのユーザーのセッションは失効します。

<div class="warn">
<p>ユーザーCSVには初期パスワードが平文で入ります。取り込んだ後のファイルは削除するなど、
取り扱いに注意してください。エクスポートしたCSVにパスワードは含まれません。</p>
</div>

## マスタ変更時の注意

- マスタの変更は**監査ログに記録されます**。
- MBOM・工順の保存は一括置換です。設計変更のときは、変更後の全体像を組み立ててから保存してください。
- 工順を変更しても、**すでに工程展開済みの作業指示は変わりません**。新しい工順は、それ以降に工程展開する指図から適用されます。
- 使わなくなった品目は削除ではなく **無効化** してください。過去の実績・ロットとの紐付けが保たれます。
