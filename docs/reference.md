## ステータス一覧

### 製造指図

| 状態 | 意味 | この状態でできること |
|---|---|---|
| 未承認（下書き） | 登録直後 | 承認、変更、取消 |
| 承認済 | 承認された | 工程展開、取消 |
| 展開済 | 作業指示に展開された | 取消のみ（内容変更は不可） |
| 完了 | すべて完了した | — |
| 取消 | 取り消された | — |

### 作業指示

| 状態 | 意味 | 次の操作 |
|---|---|---|
| 未配布 | 工程展開直後 | 差立、着手 |
| 配布済 | 作業者・設備が割り当てられた | 着手 |
| 着手 | 作業開始が記録された | 実績登録 |
| 完了 | 実績が登録された | 製造完了承認 |
| 承認済 | 承認され確定した | — |
| 取消 | 指図取消に連動 | — |

### 在庫ステータス（ロット）

| 状態 | 意味 | 主な設定元 |
|---|---|---|
| 正常 | 通常どおり使用・出荷できる | 受入、検査合格 |
| 保留 | 一時的に使用を止めている | 手動設定、不適合の「保留」指示 |
| 検査待ち | 検査指示が発行された | 検査指示の発行時に自動 |
| 不良 | 検査不合格 | 検査判定「不合格」時に自動 |
| 廃棄予定 | 廃棄する予定 | 手動設定、不適合の「廃棄」指示 |

### 検査指示

指示 → 実施中 → 判定済 → 承認済（／取消）

### 不適合

発生（未対応） → 対応指示済 → 対応完了 → クローズ

### ピッキング指示・出荷指示・保全指示

指示 → 完了（／取消）

### 棚卸

指示（実棚入力中） → 確定（／取消）

### 保全計画

計画 → 指示発行済 → 完了（／取消）

### トラブル報告

発生 → 対応中 → 完了

### 出荷判定

判定結果は 可／保留／特別採用。それぞれに 未承認／承認済 の状態があります。

## 採番規則

すべて **業務日付** を基準に、その日ごとの連番で採番されます。

| 対象 | 形式 | 例 |
|---|---|---|
| 製造指図番号 | `MO` + 日付 + 4桁連番 | `MO20260501-0001` |
| ロット番号 | 品目コード + 日付 + 3桁連番 | `PRD-100-20260501-001` |
| ピッキング指示番号 | `PK` + 日付 + 4桁連番 | `PK20260501-0001` |
| 出荷番号 | `SH` + 日付 + 4桁連番 | `SH20260501-0001` |
| 棚卸番号 | `ST` + 日付 + 4桁連番 | `ST20260501-0001` |
| 検査指示番号 | `IN` + 日付 + 4桁連番 | `IN20260501-0001` |
| 不適合番号 | `NC` + 日付 + 4桁連番 | `NC20260501-0001` |
| 保全指示番号 | `MT` + 日付 + 4桁連番 | `MT20260501-0001` |
| 出荷判定書番号 | `SJ` + 日付 + 4桁連番 | `SJ20260501-0001` |

受入時のロット番号は、入力欄を空欄にすると自動採番されます。
納入元のロット番号を使いたい場合は手入力またはスキャンしてください。

## 業務日付（製造日）

日次の集計と採番は、暦日ではなく **業務日付** で行われます。

- 既定の境界時刻は **午前6時** です。
- 午前6時より前の時刻は、**前日の製造日**として扱われます。
- 例：5月2日 午前3時の実績 → 製造日は「5月1日」

夜勤の日跨ぎ実績を1つの製造日にまとめるための仕組みです。
境界時刻は設定で変更できます（[管理者向け運用](operations.html#settings)）。

業務日付が使われるのは、各種番号の採番と、品質分析の期間指定です。

## 主要な業務ルール

| ルール | 内容 |
|---|---|
| 工程展開には工順が必要 | 品目に工順（BOP）が登録されていないと工程展開できません |
| 承認しないと展開できない | 製造指図は「承認済」でのみ工程展開できます |
| 工程の順序は強制しない | 前工程が終わっていなくても後工程に着手できます。着手順は差立で管理します |
| 最終工程で在庫計上 | 工順の最後の工程の実績登録時に、良品数が産出ロットとして入庫されます |
| バックフラッシュはMBOM基準 | MBOM × (良品数 + 不良数) を先入れ先出しで自動消費します |
| ピッキングは先入れ先出し | 有効期限を優先して自動引当されます |
| 出荷には出荷判定が必要 | 承認済みの「可」または「特採」判定がないと出荷実行できません |
| 承認は単段階 | 各種承認は1回の承認操作で確定します（多段階ワークフローはありません） |
| 訂正には理由が必要 | 数量調整・検査実績訂正には理由の入力が必須で、監査ログに記録されます |
| 記録は消せない | 監査ログは追加されるだけで、画面からもAPIからも変更・削除できません（[監査ログ](operations.html#audit-log)） |

## 画面のない機能（APIのみ提供）  {#api-only}

次の機能はAPIには実装されていますが、Web画面からは操作できません。

| 機能 | 代替手段 |
|---|---|
| 部材投入の手動記録 | 実績入力の**バックフラッシュ**、または出庫・払出の**ピッキング実行** |
| 作業時間の記録（直接／間接） | 実績入力の開始時刻・終了時刻、段取り実績の時刻 |
| 工程間の搬送・移動指示 | 在庫照会・操作の**移動** |

## 用語集

| 用語 | 意味 |
|---|---|
| 製造指図 | 「この品目をこの数だけ作る」という単位。品目 × 数量 |
| 作業指示 | 製造指図を工程ごとに分解したもの。品目 × 工程 |
| 工程展開 | 製造指図を工順に基づいて作業指示に分解すること |
| 差立（ディスパッチング） | 作業指示に作業者・設備・着手順を割り当てること |
| MBOM | 製造用の部品構成表。親1単位あたりの子品目と数量 |
| 工順（BOP） | 工程の順序と、各工程の標準時間・必要スキル・設備・治工具の定義 |
| BOE | 工順に紐づく設備情報 |
| 産出ロット | 製造指図の工程展開時に採番される、製品側のロット |
| バックフラッシュ | MBOMと完了数量から部材消費を自動計算して在庫を引き落とす仕組み |
| 段取り | 作業前（前段取り）・作業後（後段取り）の準備・片付け作業 |
| 特別採用（特採） | 規格を外れているが、条件付きで使用・出荷を認める判定 |
| トレースバック | ある製品ロットに使われた部材ロットをさかのぼること |
| トレースフォワード | ある部材ロットが使われた製品ロットを追うこと |
| 逸脱／不適合 | 規格や手順から外れた事象。不適合管理で対応を記録します |
| HSE | Health, Safety, Environment。健康衛生・安全に関するチェック項目 |
| QCDS | Quality（品質）／Cost（コスト）／Delivery（納期）／Safety（安全）。トラブルの分類 |
| 業務日付（製造日） | 集計・採番に使う日付。既定では午前6時が境界 |
