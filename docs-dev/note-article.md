# 紙とExcelの製造記録から一歩進む ― 無償のMES「Parallel Factory MES」を小さな工場で動かすまで

【見出し画像：dashboard.webp】

「どのロットの部材が、どの製品に使われたのか」
「この不良品、誰がいつ作業したのか」

お客様から問い合わせが来たとき、紙の作業日報とExcelの在庫表を何冊もめくって答えを探していませんか。

手書きの記録には、間違いと手間がつきものです。

- ロット番号や数量の書き間違い、読めない字
- 書き忘れや、日報の出し忘れ
- 紙の日報をExcelへ打ち直す転記の手間と、そのときの打ち間違い
- 月末の集計や、問い合わせへの回答に何時間もかかる

記録そのものは毎日がんばって残しているのに、いざというときに頼りにならない。

従業員数十人規模の工場では、MES（製造実行システム）は「大企業が何千万円もかけて入れるもの」と思われがちです。けれど、記録を残して後からたどれるようにしたい、という悩みは規模に関係ありません。

そうした工場でもライセンス費用なしで使えるMESとして **Parallel Factory MES** を個人で開発し、無償で公開しています。

この記事では、Parallel Factory MES を、小・中規模の工場で**導入してから日々運用するまで**の流れを紹介します。細かい操作はユーザーガイドにまとめてあるので、ここでは「何を、どの順番で、どこに気をつけて進めればよいか」に絞ってお話しします。

ユーザーガイド：https://msmsrep.github.io/ParallelFactoryMES/index.html

## Parallel Factory MES でできること

ブラウザだけで使える製造実績の記録・追跡システムです。現場のPCやタブレットに専用アプリを入れる必要はありません。

- **製造指図から出荷までを一本の流れで管理**：製造指図 → 工程ごとの作業指示 → 実績 → 在庫 → 検査 → 出荷判定 → 出荷
- **ロット単位で双方向に追跡**：どの部材ロットからどの製品ロットができたか、製品から部材へ、部材から製品へたどれます
- **「誰が・いつ」が必ず残る**：実績の訂正、マスタ変更、在庫調整などは監査ログに記録されます
- そのほか、受入・棚卸などの在庫管理、検査と不適合の対応、設備保全と治工具の寿命管理、作業指示書や現品票（バーコード付きラベル）の印刷にも対応しています

ライセンスキーもアクティベーションも要りません。

【画像：trace.webp（トレーサビリティ画面）】

## ステップ1：入手方法を選ぶ

入手方法は3通りあります。最初の一歩は「1台で試す」から始めるのがおすすめです。

**① まず1台で試す → Microsoft Store 版**
Windows 10（2004 以降）/ 11 のPCにストアからインストールするだけです。初期管理者も自動で作られるので、インストール直後から触れます。ただし、ほかの端末からは接続できません。機能の確認や、自社の業務に合うかどうかの検証向けです。

**② 現場で使う → ZIP 版（Windows / Linux）**
社内LANのサーバー（普通のPCでも可）に置き、現場の端末からブラウザでアクセスします。ZIPを展開して、Windowsなら `start.cmd` をダブルクリックするだけで起動します。.NET などのインストールは不要です。

**③ コンテナで動かす → Docker 版**
Docker が使える環境ならこちら。データを残すため、ボリューム指定（`-v mesapp-data:/data`）を忘れずに付けてください。

```
docker run -d -p 8080:8080 -v mesapp-data:/data ghcr.io/msmsrep/parallelfactorymes
```

> 💡 Windows で ZIP を展開して「WindowsによってPCが保護されました」と出たら、展開前にZIPファイルのプロパティで「許可する」にチェックを入れてから展開し直してください。

データベースの準備は不要です。初回起動時に、データ保存用のファイル（SQLite）が自動で作られます。

## ステップ2：初期管理者を作ってログイン

ZIP版・Docker版では、初めてブラウザで開くとログイン画面に「初期セットアップが必要です」と表示されます。**初期管理者アカウントを作成** からユーザー名・氏名・パスワードを入れれば、システム管理者のアカウントができます。

パスワードは **8文字以上で、英小文字と数字を含む** ことが条件です。この初期セットアップ画面は、ユーザーが1人もいないときにしか使えません。管理者のパスワードは大切に保管しておきましょう。

## ステップ3：まずはサンプルデータで全体をつかむ

いきなり自社のデータを入れる前に、サンプルデータで「製造から出荷まで」をひと通り体験しておくと、あとのマスタ設計がぐっと楽になります。

サンプルは「ギアポンプ10台を作って出荷する」小さな工場の設定です。加工ライン・組立ライン・検査室・出荷エリアがあり、生産管理・物流・作業者・品質担当の数人で回している、という想定です。まさに小規模工場の縮図になっています。

1. GitHub Releases から**マスタのサンプル**ZIPを入手し、**マスタ管理**の「ZIPで一括取込」で取り込む
2. 続けて**実績のサンプル**ZIPを、**管理 → 実績CSV取込**の「ZIPで一括取込」で取り込む

これで、製造指図・作業実績・検査・出荷・保全・在庫の記録がそろった状態になります。途中までの指図も入っているので、工程展開や出荷判定の承認を自分の手で動かせます。

ガイドの「サンプルで見る 製造から出荷まで」や「工場模型で見る 製造から出荷まで」（15の場面で、物が動くとどの記録が変わるかを見られる）と並べて触ると、流れがつかみやすいはずです。

> 💡 試し終わったら、サーバーを止めて `mesapp.db` 関連のファイル（`-wal` / `-shm` を含む）を消して再起動すると、まっさらな状態に戻ります。ファイルの保存先は既定で `%LOCALAPPDATA%\ParallelFactoryMES`（Linux は `~/.local/share/ParallelFactoryMES`）です。

【画像：orders.webp（製造指図画面）】

## ステップ4：自社のマスタを登録する（順番が大事）

いよいよ本番の準備です。マスタには**登録の順番**があります。ここを間違えると、製造指図を工程ごとの作業指示に展開できません。

1. **工程**（切削・組立・検査など）
2. **品目**（製品・半製品・部材をすべて「品目」として登録）
3. **MBOM**（部品構成。親1単位あたりに何をいくつ使うか）
4. **工順（BOP）**（どの工程をどの順に通るか）
5. **ロケーション**（倉庫・置場）
6. **設備・治工具・検査項目・チェックリスト・スキル・ユーザー**

小さな工場で最初から全部をきっちり作り込む必要はありません。おすすめは、**まず主力製品1つ分だけ**を 工程 → 品目 → MBOM → 工順 まで作って、製造指図を1件流してみることです。動きを見てから品目を増やしていくほうが、手戻りが少なく済みます。

品目が多い場合は、CSVでの一括登録が使えます。今Excelで管理している品目表があるなら、サンプルCSVの列に合わせて貼り替えるのが早道です。

登録で気をつけたいポイントを3つ。

- **品目コードはロット番号の先頭にも使われます**。現場で読みやすいコード体系にしておきましょう
- 使わなくなった品目は**削除ではなく「無効化」**。過去の実績やロットとのつながりが保たれます
- 工順を変えても、**すでに展開済みの作業指示は変わりません**。新しい工順はそれ以降の指図から適用されます

【画像：masters.webp（マスタ管理画面）】

## ステップ5：利用者とロールを決める

ユーザーは システム管理者が **マスタ管理 → ユーザー** から追加します。ロール（役割）は7種類あります。

- システム管理者
- 生産管理担当者
- 現場作業者
- 物流・倉庫担当者
- 品質管理担当者
- 品質保証担当者
- 設備保全担当者

ロールは**1人に複数付けられる**ので、兼務の多い小さな工場でも困りません。たとえば「倉庫担当が受入検査もする」なら、物流・倉庫担当者＋品質管理担当者を付けます。

ガイドにもあるとおり、小規模な運用なら **システム管理者1名と、業務ごとのロールを付けたユーザーを数名** で十分です。権限のない操作はボタン自体が表示されないので、現場の画面がシンプルに保てます。

管理者が作ったユーザーは、初回ログイン時にパスワード変更を求められます。

## ステップ6：現場で使えるようにする

現場の作業者は、作業指示の一覧から自分の担当分を開いて、段取り・チェックリスト・実績を記録します。

【画像：workorders.webp（作業指示画面）】

### バーコードを活かす

受入した部材には、その場で**現品票（ロット番号のバーコード付きラベル）**を印刷して貼りましょう。以降のピッキング照合・検査・トレースがスキャンで進むようになります。ロット番号を手で書き写す必要がなくなるので、書き間違いも防げます。USBのバーコードリーダーならそのまま使えます。

作業指示書には、その工程で使う部材（代替部品を含む）が載るので、工程に配っておくと部材の取り違え防止にもなります。

帳票は印刷用ページが別タブで開くので、普通にプリンタで印刷するか、「PDFとして保存」で残せます。

【画像：print-lot.webp（現品票）】

### タブレットのカメラで読みたいなら HTTPS に

注意点がひとつあります。**タブレットやスマホのカメラでバーコードを読む場合、HTTPS が必須**です（ブラウザの仕様）。HTTPのままでも、USBリーダーと手入力は動きます。

アプリ自身はHTTPSを強制しないので、IIS や nginx をリバースプロキシとして前に置き、そこでHTTPSを受けます。社内LANなら mkcert や社内CAで証明書を作る手順がガイドの「管理者向け運用」にまとまっています。

### 夜勤がある工場は「業務日付の境界」を設定

夜勤で日付をまたぐ工場では、「深夜2時の実績は前の日の扱いにしたい」ということがよくあります。Parallel Factory MES には**業務日付の境界時刻**の設定があり、既定は午前6時です。シフトの始まりに合わせて変えておくと、集計や採番の日付が現場の感覚と一致します。

## ステップ7：日々の運用で押さえておくこと

### バックアップ

既定のSQLiteで運用する場合、**稼働中のDBファイルを単純にコピーしないでください**。壊れたコピーになることがあります。安全な方法は次の2つです。

- サーバーを止めてから `mesapp.db` をコピーする
- 稼働中なら SQLite の `VACUUM INTO` でバックアップを作る

始業前や終業後に止めてコピーする、という運用でも十分です。

### 監査ログ

実績の訂正・検査の訂正・マスタ変更・在庫調整などは、すべて監査ログに残ります（閲覧はシステム管理者のみ）。「いつの間にか数字が変わっている」という事態をあとから確かめられるので、品質監査や顧客監査の場面でも頼りになります。記録は画面からもAPIからも変更・削除できず、増えていくだけです。保持期間は5年（設定で変更可）で、期間を過ぎても自動では削除されません。

### データベースを選ぶのは運用開始前に

既定のSQLiteは追加のインストールが要らず、**数十端末規模まではそのまま運用できます**。小・中規模の工場ならほとんどの場合これで足ります。

同時に書き込む端末が多い、データ量が大きい、既存のDBサーバーでまとめて管理したい、といった場合は PostgreSQL か SQL Server に切り替えられます。ただし**既存のSQLiteのデータは移せません**。どのデータベースを使うかは、本番運用を始める前に決めておきましょう。

## できないこと（導入前に知っておきたい）

正直にお伝えしておくと、今のバージョンでは次のことには対応していません。

- 設備・秤量機からの自動データ収集（実績は手入力・スキャン）
- EDI / ASN 連携
- シリアル番号（1台ずつの個体）単位の追跡（ロット単位のみ）
- 多段階の承認ワークフロー（承認は1段階）

逆に言えば、「まずは紙とExcelの記録をシステムに載せ、ロットで追えるようにする」という最初の一歩には十分な機能がそろっています。

## おわりに

小さな工場のシステム化は、「全部を一度に変える」より「1製品・1ラインから始めて広げる」ほうがうまくいきます。

1. Microsoft Store 版で1台で触ってみる
2. サンプルデータで製造から出荷までを体験する
3. 主力製品1つ分のマスタを作って、実際の指図を1件流す
4. ZIP版・Docker版で社内LANに置き、現場に広げる

この順で進めれば、ライセンス費用をかけずに、自社に合うかどうかを確かめながら導入できます。

ユーザーガイドには、画面写真つきで各業務の操作が載っています。担当者別の入口（導入担当・現場作業者・倉庫・品質管理・品質保証）もあるので、現場のみなさんにはそのページを案内してみてください。
