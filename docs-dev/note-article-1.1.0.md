# 紙とExcelの次は「ほかのシステムとつなぐ」― Parallel Factory MES 1.1.0 で増えたこと

【見出し画像：dashboard.webp】

前回の記事では、無償のMES「Parallel Factory MES」（1.0.4）を小さな工場に導入して、日々運用するまでの流れを紹介しました。

紙とExcelの記録をMESに載せると、次にこんな声が出てきます。

「販売管理から出した製造指図を、毎朝手で取り込むのが面倒」
「設備が止まった時刻を、作業者があとから思い出して書いている」
「不良が出たら、班長のスマホにすぐ知らせたい」

MESは単独で使うより、**ほかのシステムや設備とつながったときに、はじめて本領を発揮します**。バージョン 1.1.0 では、この「つなぐ」部分を一気に足しました。

この記事では、1.0.4 から 1.1.0 で増えた機能と、小さな工場でどう使えるかを紹介します。

ユーザーガイド：https://msmsrep.github.io/ParallelFactoryMES/index.html

## 1.1.0 で増えたこと（まとめ）

- **フォルダ連携**：決めたフォルダにCSVを置くだけで、自動で取り込む
- **連携API（APIキー）**：販売管理・生産管理（ERP）や社内のスクリプトから、ログインせずにデータをやり取りする
- **設備イベントの受信**：設備の稼働・停止を、PLCからゲートウェイ経由で自動で記録する
- **Webhook**：不適合や設備の停止が起きたとき、MESからチャットなどへすぐに知らせる
- **スマホの画面幅に対応**
- **デスクトップ版（Microsoft Store）の初期管理者を、Web版と同じ初期セットアップ画面で作るように変更**

難しさの順に並べると、**フォルダ連携 → 連携API → Webhook → 設備イベント** です。プログラムを書かずに始められるのはフォルダ連携だけなので、まずはそこから紹介します。

## フォルダ連携：CSVを置くだけで取り込む

販売管理や生産管理のソフトには、たいてい「CSVで出力」の機能があります。けれど、そのCSVを毎朝MESの画面から手で取り込むのは、地味に手間がかかります。忘れることもあります。

**フォルダ連携**を使うと、決めたフォルダ（`inbox`）にCSVが置かれただけで、MESが自動で取り込みます。プログラムを書く必要はありません。

たとえば、こんな使い方ができます。

- 販売管理ソフトが毎朝出力する製造指図のCSVを、共有フォルダに保存させる
- 受入の記録を、倉庫のPCから共有フォルダに置く

取り込めたファイルは `processed`、取り込めなかったファイルは `error` フォルダへ移り、横に結果のファイルが付きます。画面から取り込むときと同じチェックを通り、**1行でもエラーがあれば、そのファイルは何も反映しません**。半端に取り込まれて困ることはありません。

> 💡 取込は、専用に作った利用者（例：`folder-link`）として行われます。この利用者には、**取り込みたい種類に必要なロールだけ**を付けてください。製造指図なら生産管理担当者、受入なら物流・倉庫担当者です。だれが取り込んだかは、監査ログにもこの利用者で残ります。

設定は、サーバーの起動時に連携フォルダと利用者を指定するだけです。システム管理者は「管理 → フォルダ連携」の画面で、設定の誤りや最近処理したファイルを確かめられます。

【画像：folder-link.webp（フォルダ連携の画面。取り込めたファイルと、エラーになったファイル）】

## 連携API：ほかのシステムからデータをやり取りする

社内に販売管理・生産管理のシステムがあって、少しプログラムを書ける人（または頼める業者）がいるなら、**連携API**が使えます。

### APIキーを発行する

システム管理者が「管理 → APIキー」でキーを発行し、連携するシステムに設定します。キーで何ができるかは、キーに紐づけた利用者のロールで決まります。フォルダ連携と同じく、**用途ごとに専用の利用者を作り、必要なロールだけを付ける**のがおすすめです。

キーは発行したときにしか表示されません。パスワードと同じように扱ってください。

### できること

- **CSVの取込**：マスタも実績も、画面と同じCSVをそのまま送れます。`?dryRun=true` を付ければ、検証だけして反映しません
- **マスタのCSV出力**
- **生産実績を「前回の続きから」読む**：ERPに完成数を渡すときなど、前回読んだところから先だけを取り出せます。あとから訂正された実績も、同じように続きから読めます

【画像：api-keys.webp（APIキーの画面）】

仕様書（OpenAPI）も公開しているので、Postman などに読み込めば、使える口や応答の形がすぐ分かります。

### 送り直しても二重にならない

通信が切れて、同じ実績CSVを送り直したら二重に登録された ― 連携でいちばん起きやすい事故です。

連携APIでは、要求に `Idempotency-Key`（送る内容ごとに決めた値）を付けておくと、**同じ内容を送り直しても取り込み直さず、前回の結果を返します**。連携する側は「失敗したら送り直す」だけで済みます。

### 版を上げても動き続ける

連携でもうひとつ怖いのが、「MESを新しい版にしたら、つないでいた仕組みが動かなくなった」ということです。

連携API（v1）とCSVの列には、**項目や列を足すことはあっても、消したり名前を変えたりはしない**という約束を決めました。CSVの列とWebhookの本文の形は基準ファイルに固定して、テストで機械的に確かめています。

## 設備イベント：設備の稼働・停止を自動で記録する

前回の記事の「できないこと」に「設備からの自動データ収集」を挙げていました。1.1.0 で、そのうち**設備の稼働状態（稼働・停止・段取り・故障など）**を自動で記録できるようになりました。

### 仕組み

MESは、PLCと直接は通信しません。間に**ゲートウェイ**（Node-RED など）を置きます。

```
設備・PLC ──▶ ゲートウェイ（Node-RED など）──▶ MES
         OPC UA・MCプロトコル・Modbus など   連携API（APIキー）
```

ゲートウェイがPLCの状態を読み、状態が変わったときにMESへ送ります。MESは届いた変化を時刻の順に並べて、「9:00〜9:10 稼働」「9:10〜9:25 停止」のような稼働履歴に組み立てます。

PLCのメーカーや通信方式は工場ごとにばらばらです。MESをそれぞれに合わせる代わりに、その差をゲートウェイで吸収する形にしました。

### 小さな工場で助かるところ

- **停止の時刻を手で書かなくてよくなる**：作業者があとから思い出して書くと、時刻はどうしてもあいまいになります
- **停止原因を自動で引き当てる**：設備のアラーム番号と停止原因の対応表を作っておけば、「A-101 → 材料切れ」のように原因が入ります。引けなかった停止は、あとから保全の画面で原因を書き足せます
- **通信が止まったことに気づける**：受信が一定時間（既定10分）途絶えると、稼働監視の画面に「受信が途絶えています」と出ます

通信が切れたときに送り直しても、同じイベントは二重に記録されません。

### すべての設備を一度につなぐ必要はない

設備ごとに「設備イベントで収集する」かどうかを選べます。**つないだ設備だけ自動、ほかの設備は今までどおり手入力**、という混在ができるので、主力の1台から始められます。手入力と自動で同じ時間を二重に数えないよう、つないだ設備は手入力できなくなります。

> 💡 Docker が使えるなら、リポジトリの `compose.yaml` で、MQTTブローカーと Node-RED のゲートウェイを一緒に起動できます（`docker compose --profile equipment up -d`）。数秒ごとに状態を変える**模擬設備**が入っているので、実機が無くても、稼働履歴が自動で増えていく様子を試せます。

【画像：equipment-current.webp（稼働監視の「設備の今の状態」）】

【画像：equipment-logs.webp（設備イベントで記録された稼働履歴。原因を引けなかった停止は、あとから書き足せる）】

## Webhook：起きたことをすぐに知らせる

連携APIは「相手が取りに来る」仕組みです。ERPが1日1回完成数を取りに来るなら、それで足ります。

けれど、**不良が出た、設備が止まった、ロットが保留になった**、というような出来事は、すぐに知りたいものです。そこで、MESのほうから登録したURLへ知らせる **Webhook** を足しました。

通知する出来事は、たとえば次のとおりです。

- 生産実績の記録・訂正
- 作業指示・製造指図の状態の変化
- ロットの在庫ステータスの変化（保留・解除など）
- 不適合の起票（検査の不合格からの自動起票も含む）
- 設備の停止・故障

通知には「設備 EQ-01 が『停止』になりました（材料切れ）。」のような1文の要約が付くので、そのままチャットに流すだけでも役に立ちます。

設定は、システム管理者が「管理 → Webhook」で送信先のURLと通知する出来事を選ぶだけです。**テスト送信**のボタンで、届くかどうかをその場で確かめられます。

受け取る側の見本として、Node-RED のフロー（署名を確かめて Slack や Teams に転送する）と、Python・PowerShell の短いスクリプトを用意しました。

届かなかった通知は、間隔を空けて自動で送り直します。それでも届かなかったものは画面に出るので、受け側を直してから再送できます。

【画像：webhook-deliveries.webp（Webhook の送信の記録）】

## スマホの画面幅でも使えるように

1.0.4 では、スマホで開くとサイドバーが画面を埋めてしまい、表も見切れていました。1.1.0 では、スマホの画面幅ではサイドバーを開け閉めでき、幅の広い表は横にスクロールできるようになりました。

現場の作業はタブレットで行いたい、班長がスマホで進捗だけ見たい、という使い方がしやすくなります。

## デスクトップ版の初期管理者のつくり方が変わりました

前回の記事で「Microsoft Store 版は初期管理者が自動で作られる」と書きましたが、1.1.0 からは変わります。

Store 版も ZIP版・Docker版と同じく、初めて開いたときに「初期セットアップが必要です」と表示されるので、**初期管理者のユーザー名とパスワードを自分で決めて作成**します。自動で生成したパスワードを控えておく手間がなくなり、どの版でも同じ手順で始められるようになりました。

## アップデートのしかた

データベースの更新は、起動時に自動で行われます。**更新の前に、必ずバックアップを取ってください。**

- **ZIP版**：サーバーを止め、データを残したまま新しいZIPを展開して起動します（データの保存先はアプリのフォルダとは別です）
- **Docker版**：新しいイメージを取得して、同じボリュームでコンテナを作り直します

```
docker pull ghcr.io/msmsrep/parallelfactorymes:1.1.0
```

- **Microsoft Store 版**：ストアから更新されます

> 💡 Webhook を使う場合、データの保存先にある `dataprotection-keys` フォルダ（Webhook の秘密の値を暗号化する鍵）もバックアップに含めてください。失うと、送信先ごとに秘密の値を作り直すことになります。

## できないこと（1.1.0 の時点）

前回挙げたものから、設備の稼働状態の自動記録はできるようになりました。今も対応していないのは次のとおりです。

- 秤量機・測定器などからの測定値の自動収集（設備イベントで取れるのは稼働状態だけ）
- EDI / ASN 連携
- シリアル番号（1台ずつの個体）単位の追跡（ロット単位のみ）
- 多段階の承認ワークフロー（承認は1段階）
- MESから外へのCSVの自動書き出し（実績は連携APIで読み出すか、Webhookで知らせます）

## おわりに

1.1.0 のテーマは「MESを工場の中で孤立させない」ことでした。

小さな工場なら、つなぐ順番は次のようにすると無理がありません。

1. **フォルダ連携**で、今手で取り込んでいるCSVを自動にする（プログラム不要）
2. **Webhook**で、不適合や設備の停止をチャットに流す
3. 主力の設備1台を、**設備イベント**で自動記録にする
4. ERPとの連携が必要になったら、**連携API**でつなぐ

どれも無償で、ライセンスキーも要りません。まずはサンプルや模擬設備で試してみてください。
