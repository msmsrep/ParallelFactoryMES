# 工場模型で見る 製造から出荷まで 仕様書

サンプルのギアポンプ製造を、**動く工場模型**と、それに連動する **MES の記録の変化**で見せるガイドの新ページを作る。
1カード＝1セッションで進める（`Orchestration.md` §4.1）。カードの間はセッションをクリアし、次へ進む前に前のカードをコミットする。
新しいセッションでは「`docs-dev/FactoryTour.md` の TOUR-01 を実行して」とだけ頼めば着手できるように書いてある。

## 背景

`docs/walkthrough.md` は図と画面写真で流れを説明しているが、次の理由で分かりにくい。

- 図が箱と矢印の抽象図で、**工場のどこで起きているか**が見えない
- 物の動きと記録の変化が別々の章にあり、読者が頭の中でつなぐ必要がある

このページで伝えることは1つ。**「現場で物が動くと、誰がどの画面に入力し、MES のどの記録が変わるか」**。

## 決定事項（2026-11-03）

| 論点 | 決定 | 理由 |
|:--|:--|:--|
| 置き場所 | 新しい全幅ページ `docs/factory-tour.html`。`walkthrough.md` は画面写真つきの詳細編として残す | サイドバーがなく模型を大きく見せられる。操作の詳細は既存ページに任せられる |
| 進め方 | 先に5場面で見た目と操作を確かめ、利用者の確認後に15場面へ広げる | 演出を確かめる前に全場面のデータを作ると、手戻りが大きい |
| 描画 | 等角投影の SVG を素の JavaScript で生成する。外部ライブラリ・ビルド・外部通信なし | 説明に回転は不要。軽く、日本語ラベルが鮮明で、GitHub Pages にそのまま置ける |
| 場面の持ち方 | 描画処理と場面データを分ける | サンプルが変わってもデータの修正で済む |
| 動きの進行 | 既定は「次へ」で1場面ずつ。「再生」を押すと自動で進む | 読む速さは人によって違う |
| 反映の見せ方 | 信号は**人の端末から** MES へ飛ばす。設備から直接は飛ばさない | 設備からの自動収集は将来拡張（Spec.md 3章の製造実施・設備稼働報告）。実際にない連携に見せない |
| 数値の正 | `samples/actual-csv` の **01〜15 だけを取り込んだ時点**の値 | 16 以降の在庫操作（24 の払出戻し、30 の保管サンプルなど）まで含めると、物語の数字とずれる |
| 多言語 | 日本語のみ | ユーザーガイド全体が日本語のみで、`I18nCheck.ps1` の対象外 |

`Spec.md` は変更しない（アプリの機能を変えない、説明用のページのため）。

## 対象外

- 本物の3D表示（カメラの回転・拡大）、動画の書き出し
- アプリ本体（`src/`）への組み込み、実データとの接続
- 保全・治工具・棚卸・不適合処置・リワーク（物語の外。`walkthrough.md` 10章に任せる）
- `walkthrough.md` の図の削除や作り替え（導線の追加だけを行う）

## 画面仕様

### レイアウト

幅 1000px 以上：

```
┌ ガイドへ戻る ─────── ページ名 ──────────────┐
│ ┌ 工場模型 ───────────┐ ┌ 場面 6／15 ────┐ │
│ │                      │ │ タイトル・日時  │ │
│ │  等角の工場          │ │ 現場で起きること│ │
│ │  物・人・信号が動く  │ │ 誰がどの画面に  │ │
│ │                      │ │ MESで変わること │ │
│ └──────────────────────┘ │ 詳しく見る →    │ │
│ [◀ 前へ][▶ 再生][次へ ▶] └─────────────────┘ │
│ ○─○─○─●─○─○  場面の列（押すと移動）         │
│ ┌ MES の台帳 ─ 在庫 ──────── 作業指示の状態 ┐ │
│ └───────────────────────────────────────────┘ │
└───────────────────────────────────────────────┘
```

幅 1000px 未満：模型 → 操作 → 説明 → 台帳の縦積み。横スクロールは出さない。

スマホ幅（375px）では全景だとラベルが読めないので、**カメラ（SVG の viewBox）を今の持ち場に寄せる**。ラベルは今の場面に関わるものだけ出す。

### 工場の配置

U字の流れとする。下の配置図は並びの正とし、座標は `TOUR-01` で見た目を見ながら決める。

```
                    事務所（pm001）
                    
受入ヤード → WH-M01／WH-M02 → WC-MC1 ─────────→ 搬出口 → 外注先（工場の外）
             部材倉庫        EQ-01・EQ-05                     │
               │             WIP-01                           │
               │ 部材                                         │
               └──────────────────────┐                       ▼
出荷ヤード ← WH-P01 ← WC-PK1 ← WC-QC1 ← WC-AS1 ←──────── WIP-02
（SHIP-01）  製品倉庫  EQ-04    EQ-03    EQ-02
```

| 模型の要素 | 表し方 |
|:--|:--|
| 作業区・倉庫 | 床に区画を引き、コードと名前のラベルを付ける（`WC-MC1 機械加工`） |
| 設備 | 箱を組み合わせた簡単な形。実績のあった設備だけ使う（加工は EQ-01。EQ-05 は置くだけ） |
| 物 | 色分けした小さな立方体。部材・半製品・製品で形か色を変え、数量ラベルを付ける |
| 人 | ロール色の簡単な人形と、ユーザーID。持ち場に立つ |
| 端末 | 人の横に小さなタブレット。入力するときに光る |
| トラック | 受入ヤード、搬出口、出荷ヤード |

対象外の置場（WH-S01 保全部品棚）は模型に置かない。

### 1場面の演出（4拍）

1. **現場が動く**：物が持ち場へ移動し、設備が動く
2. **人が入力する**：端末が光り、右の「誰がどの画面に」が強調される
3. **信号が飛ぶ**：端末から MES へ点線が流れる
4. **記録が変わる**：台帳の数字が変わり、変わった行を約1秒強調する

異常のある場面では、持ち場を赤く光らせ、説明に赤の項目を足す。

### MES の台帳

| 欄 | 内容 |
|:--|:--|
| 在庫 | 下の9ロットの置場と数量。まだ無いロットは薄く表示する |
| 作業指示の状態 | `SMP-SF-001-10` など5件の状態 |
| 説明 | 「部材は作業指示への投入で減る」「在庫に入るのは最終工程の良品だけ」など、数字の見方を場面に応じて短く添える |

スマホ幅では変わった行だけを出し、「すべて表示」で開く。

場面を飛ばしても台帳が合うように、各場面は**差分**を持ち、1場面目から足し直して表示する。

### 操作

| 操作 | 動き |
|:--|:--|
| 次へ | 次の場面の4拍を再生する。再生中に押すと今の場面を最終状態にしてから進む |
| 前へ・場面の列 | 移動先の最終状態をアニメーションなしで表示する |
| 再生／一時停止 | 4拍の後、説明を読む時間（約5秒）を置いて次へ進む。最後の場面で止まる |
| キーボード | ← → で前後、Space で再生・一時停止 |
| URL | `#scene-6` で該当場面を開く。場面を移ると URL も変わる |

### 見た目とアクセシビリティ

- ロール色は `docs/assets/style.css` の `--r-pm` `--r-op` `--r-lg` `--r-qc` `--r-ng` をそのまま使う（ガイドの図と色を合わせる）。模型の本体は無彩色
- ダークモードは `prefers-color-scheme` で追従する（ガイドと同じ。切替ボタンは置かない）
- `prefers-reduced-motion: reduce` では動かさず、各場面の最終状態だけを表示する。自動再生の間隔はそのまま使える
- 説明と台帳は SVG の外の HTML に置く。場面が変わったら `aria-live="polite"` で要約を読み上げる。SVG には場面ごとの説明を `aria-label` で付ける
- 色だけで伝えない（異常には「逸脱」などの語を添える）
- JavaScript が無いときは `<noscript>` で `walkthrough.html` へ案内する

### 場面データの形

```js
{
  id: 'machining',            // 変えない。#scene-6 の番号はこの並びから決まる
  title: '夜勤で機械加工',
  when: '9/1 21:00〜9/2 3:00（夜勤 N）',
  station: 'WC-MC1',          // カメラと強調の対象
  actors: [{ user: 'op003', role: 'op', at: 'WC-MC1' }],
  moves: [{ item: 'casting', qty: 20, from: 'WH-M01', to: 'WC-MC1' }],
  floor: '現場で起きること（1〜2文）',
  input: { who: 'op003', menu: '生産・製造実行 → 作業指示 → 実績入力', record: '投入・良品数・製造条件' },
  effects: [{ lot: 'R3001-260901', delta: -20 }, { wo: 'SMP-SF-001-10', status: '完了' }],
  alerts: [{ at: 'WC-MC1', text: '送り速度 1350 が許容範囲外（逸脱）' }],
  note: '数字の見方の補足',
  detail: { href: 'walkthrough.html#execution', image: null }
}
```

`detail.image` には、**その場面と同じ記録を写した写真だけ**を指定する。無理に当てはめない（`record.webp` は組立の画面なので、機械加工には使わない）。

### TOUR-01：描画処理と第1段階の5場面

- **作るもの**：`factory-tour.html`、`assets/tour/` の3ファイル、`.claude/launch.json` の確認用設定
- **まだしないこと**：ガイドからのリンク（直接 URL で確認する）
- **受入基準**
  1. 上の5場面が、4拍の演出つきで順に再生できる
  2. 「操作」の表のとおりに動き、場面を飛ばしても台帳の値が合う
  3. 台帳と作業指示の状態が、**01〜15 だけを新しい DB に取り込んだ実データ**と一致する（確認手順は下）
  4. 幅 1440／768／375px で横スクロールが出ず、模型のラベルが読める
  5. ライト・ダーク・`prefers-reduced-motion` のそれぞれで表示が崩れない
  6. コンソールエラーなし、外部へのリクエストなし
  7. `jekyll build -s docs -d "$env:TEMP\mes-docs-site"` が成功する
- **完了時**：スクリーンショットを利用者に渡し、**見た目と操作の確認を受けてから TOUR-02 に進む**

### TOUR-02：残り10場面

- **作るもの**：`scenes.js` への10場面の追加。必要な演出だけ `tour.js` に足す（トレースの光、測定値の帯など）
- **受入基準**
  1. 15場面すべてが順に再生でき、つなぎの表示が残っていない
  2. 各場面の担当・メニュー・数値が、サンプルCSVと `NavMenu.razor` の表記に一致する
  3. TOUR-01 の受入基準 2〜7 を15場面で満たす

### TOUR-03：ガイドからの導線と仕上げ

- **作るもの**：`_config.yml` のナビ（`walkthrough.html` の直前に「工場模型で見る 製造から出荷まで」）、`index.md` と `walkthrough.md` 冒頭からのリンク、`intro.html` からのリンク（任意）
- **受入基準**
  1. ガイドの目次・`index.md`・`walkthrough.md` からページへ行け、ページからガイドへ戻れる
  2. 各場面の「詳しく見る」が `walkthrough.md` の該当章へ飛ぶ
  3. `jekyll build` が成功し、`docs/_site` を作っていない

## 確認の手順

新しい DB に `samples/master-csv` の ZIP と、`samples/actual-csv` の **01〜15 だけ**の ZIP を取り込む（新しい DB の用意は既存の手順に従う）。在庫照会・作業指示の一覧の値を「台帳の初期値と最終値」と比べる。

**TOUR-01 で実データから確かめること**（CSV だけでは決まらない）：

- 良品＋不良が指示数に達した `SMP-SF-001-20`（19＋1）と `SMP-FG-001-30`（9＋1）の状態が「完了」になること
- 取込後の各ロットの在庫ステータス

## 既存ページへの申し送り

`walkthrough.md` の「鋳造品は残り30個」「9台→4台」は 01〜15 の時点の値。サンプルを全部取り込むと、24 の払出戻し（R3001 +1）と 30 の保管サンプル（FG1000-S001 −1）で値が変わるはずなので、`walkthrough.md` の説明と在庫照会の写真が今のサンプルと合っているかを TOUR-03 で確認する。

CSV の実績には作業者の列がない。模型に出す担当者はユーザーマスタの所属・シフトと `walkthrough.md` の記述に合わせた（夜勤の機械加工は op003）。
