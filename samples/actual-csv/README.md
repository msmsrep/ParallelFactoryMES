# サンプル実績CSV

[`samples/master-csv/`](../master-csv/) のマスタを取り込んだ後に、**ファイル名の番号順**に取り込むサンプル実績です。
実績はマスタのコード（品目コード・ロケーションコードなど）で参照します。

全体の流れは次の4つです。マスタのZIP→このフォルダのZIPの順に1回ずつ取り込むだけで、各画面に記録が出ます。

1. **製造から出荷まで**（01〜17）：受入 → 製造指図 → 段取り・投入・出来高 → 検査 → 出荷。設備稼働とリワーク指図も
2. **保全と治工具・校正**（18〜22）：16 の故障・停止に対する突発依頼と保全実績、治工具の利用実績と引当、検査機の校正
3. **在庫と物流**（23〜27）：在庫オペレーション、搬送、ピッキング（期限切れロットを避ける先入れ先出し）、棚卸
4. **品質のフォロー**（28〜29）：10 の受入検査で起票された不適合の処置、保管サンプル

画面から操作して試すこと（保全実績の登録、指示のまま残した搬送・ピッキング・棚卸、特採の承認など）は、
ユーザーガイドの「サンプルで見る 製造から出荷まで」10章にまとめてあります。

## 取り込み方

画面上部の **ZIPで一括取込** に、このフォルダのCSVをまとめたZIPを渡せば1回で取り込めます。個別に取り込むときは、メニューの **管理 → 実績CSV取込** の種別ごとのパネルから取り込みます（受入は在庫・物流、製造指図は生産管理、
段取り〜製造条件データと作業時間は現場記録、検査は品質管理、出荷判定は品質保証、出荷指示・出荷実行は在庫・物流の権限が必要。トラブル報告・保全指示（突発依頼）・保全実績・治工具の利用実績は誰でも取り込めるが、計画保全の指示は保全担当者とシステム管理者だけ。治工具の引当は生産管理、検査機の校正は品質管理、在庫オペレーション・搬送・ピッキング・棚卸は在庫・物流、サンプル品保管は品質管理。不適合の起票と対応記録は誰でもできるが、対応指示と承認は品質管理）。種別はファイル名の `_` より後ろです
（`05_consumptions.csv` と `07_consumptions.csv` はどちらも `consumptions`、`02` と `17` はどちらも `manufacturing-orders`）。

APIへ直接送ることもできます。

```
POST /api/actuals/csv/receiving?dryRun=true   … 検証のみ
POST /api/actuals/csv/receiving               … 取込
GET  /api/actuals/csv/kinds                   … 対応種別と列の説明
GET  /api/actuals/csv/receiving/template      … ヘッダーだけのCSV
```

## 日付と期限について

サンプルの作業時刻は **2026-09-01〜09-03** に固定しています（受入日・製造日・採番の日付だけは取り込んだ日）。

- ダッシュボード・品質分析・生産性などの期間指定の画面は「今日」を基準に開くので、何も出ないときは
  **基準日を 2026-09-03 に変えるか「◀ 前へ」で戻して**見てください
- 期限切れのロット（R3006-250801、期限 2026-08-31）は取り込んだ日によらず期限アラートに出ます。
  期限間近のロット（R3004-251001、期限 2026-10-31）が「間近」に見えるのは 2026年10月中だけで、それ以降に取り込むと期限切れとして出ます
- 資格の期限（`samples/master-csv/19_user-skills.csv`）も同じく固定です。op002 の SK-03 は期限切れ、ほかは 2027年以降に切れます
- 治工具の寿命は、利用実績（20）の記録日時で数えます。メンテナンスで寿命をリセットすると、リセットした時刻（取り込んだ時刻）より前の記録は数えなくなります

## きまり

- **取込は常に新規登録**です。同じファイルを2回取り込むと2回分の実績になります
  （ロット番号を指定した行は2回目に「既に存在します」で止まります）。
- **1行でもエラーがあると全件取り消されます**。在庫・ロットも残りません。
- 登録は画面から1件ずつ入れた場合と同じ処理を通るので、監査ログ・在庫トランザクションも同じように残ります。
- 受入日（製造日）・産出ロットの製造日は取り込んだ日になります。
- **作業指示は「指図番号＋工程順序」で指します**（作業指示番号は `指図番号-工程順序2桁`。例 `SMP-FG-001-10`）。
  後続の実績CSVから指せるよう、製造指図の `OrderNo` は指定しておいてください。
  `MO` で始まる番号は自動採番用のため指定できません。
- 投入するロットは**ロット番号**で指します。自動採番のロットは取り込むまで番号が分からないので、
  後で投入するロットは受入CSVで番号を指定してください。
- 日時は `yyyy-MM-dd HH:mm`（工場の時刻）で書きます。`+09:00` のようなオフセット付きでも構いません。
  生産実績は**開始日時で直を決める**ので、夜勤の実績は夜勤の時間帯に入る時刻にしてください。
- 実行記録・検査・作業時間・トラブル報告・保全実績の**記録者は取り込んだユーザー**になります（保全手順書に必要スキルがあれば、取り込んだユーザーと照合します）。
  CSVで別の作業者の名前を書く列はありません（他人の名義で実績を作れないようにするため）。
- **ピッキング指示・棚卸指示は番号を必須の手入力にします**（`PK`・`ST` で始まる番号は自動採番用のため指定できません）。実棚数CSVは棚卸番号と、明細のロット番号＋ロケーションで指します。搬送指示には番号が無いので、1行の `Execute` で実行まで進めます。
- **出荷指示は「出荷番号」で指します**。出荷判定・出荷実行のCSVから指せるよう、出荷指示CSVの `ShippingNo` は必須です
  （`SH` で始まる番号は自動採番用のため指定できません）。出荷番号が同じ行は1件の指示・1回の出荷にまとまります。
- 出荷実行には、その出荷指示を対象にした**承認済みの出荷判定（可・特採）**が要ります。判定の無い指示・保留の指示を
  出荷実行CSVに書くと、そのファイルは取り込めません。
- **保全実績は保全指示を「保全指示番号」で指します**。保全指示CSVの `MaintenanceNo` は必須です（`MT` で始まる番号は自動採番用のため指定できません）。
  番号が同じ行は1件の実績にまとまり、1行に消費部材を1つ書けます。設備の**資産管理部品**（EQ-01 の主軸ベルト MP-9001 など）は在庫引落しの対象外なので、`PartLotNumber` に書くとそのファイルは取り込めません。
- **不適合は「不適合番号」か「ロット番号」で指します**。未登録の `ReportNo` の行は新規起票です（`NC` で始まる番号は自動採番用のため指定できません）。
  検査の不合格で自動起票された不適合は番号が分からないので、`ReportNo` を空欄にして `LotNumber` で指します。そのロットに未完了の不適合が
  2件以上あるとどれか決まらないので、その行は取り込めません（`ReportNo` で指してください）。
- `DV-03`（校正期限切れ）は 22 の校正を取り込むまで検査に使えません。22 より前のファイルで `DeviceCode` に書くと、その検査は取り込めません。
- 部材はバックフラッシュ（`Backflush=true`）でも消費できます。引くのは**その工程で使う部材だけ**で、
  サンプルのMBOMでは部材をすべて最初の工程（`Sequence=10`）で使います。部材を使わない工程（20・30）の行を
  `Backflush=true` にすると、そのファイルは取り込めません。また代替部品は消費されない（主材料だけを引く）ので、
  代替部品を使ったときは投入CSVで理由とともに投入してください。
