# サンプル実績CSV

[`samples/master-csv/`](../master-csv/) のマスタを取り込んだ後に、**ファイル名の番号順**に取り込むサンプル実績です。
実績はマスタのコード（品目コード・ロケーションコードなど）で参照します。

| # | ファイル | 種別 | 内容 |
|---|---|---|---|
| 01 | `01_receiving.csv` | 受入 | 部材・代替部材・保全部品の受入。ロット番号の指定／自動採番、有効期限あり／なしの書き分け |
| 02 | `02_manufacturing-orders.csv` | 製造指図 | 登録→承認→工程展開まで一度に進める行と、承認まで・未承認のままの行 |
| 03 | `03_setup-records.csv` | 段取り実績 | 前段取り・後段取り、異常内容の記録 |
| 04 | `04_checklist-records.csv` | チェックリスト実施 | 同じ指図・工程・チェックリストの行が1回の実施になる。任意項目の未チェック |
| 05 | `05_consumptions.csv` | 部材投入 | ハウジング加工（SF-2000）の鋳造品投入 |
| 06 | `06_production-records.csv` | 生産実績 | SF-2000 の実績。夜勤（21:00開始）の実績、最終工程の入庫と不良理由の内訳 |
| 07 | `07_consumptions.csv` | 部材投入 | ギアポンプ（FG-1000）の投入。06 で入庫した半製品ロットと、理由付きの代替部品 |
| 08 | `08_production-records.csv` | 生産実績 | FG-1000 の実績。最終工程で製品倉庫へ入庫 |
| 09 | `09_data-records.csv` | 製造条件データ | 工程管理項目との照合（送り速度 1350 は許容範囲外で逸脱になる）と自由記述 |

## 取り込み方

画面はまだありません。API に CSV を送ります（受入は在庫・物流、製造指図は生産管理、
段取り〜製造条件データは現場記録の権限が必要）。種別はファイル名の `_` より後ろです
（`05_consumptions.csv` と `07_consumptions.csv` はどちらも `consumptions`）。

```
POST /api/actuals/csv/receiving?dryRun=true   … 検証のみ
POST /api/actuals/csv/receiving               … 取込
GET  /api/actuals/csv/kinds                   … 対応種別と列の説明
GET  /api/actuals/csv/receiving/template      … ヘッダーだけのCSV
```

## きまり

- **取込は常に新規登録**です。同じファイルを2回取り込むと2回分の実績になります
  （ロット番号を指定した行は2回目に「既に存在します」で止まります）。
- **1行でもエラーがあると全件取り消されます**。在庫・ロットも残りません。
- 登録は画面から1件ずつ入れた場合と同じ処理を通るので、監査ログ・在庫トランザクションも同じように残ります。
- 受入日（製造日）・産出ロットの製造日は取り込んだ日になります。
- **作業指示は「指図番号＋工程順序」で指します**（作業指示番号は `指図番号-工程順序2桁`。例 `SMP-FG-001-10`）。
  後続の実績CSVから指せるよう、製造指図の `OrderNo` は指定しておいてください。
  `MO` で始まる番号は自動採番用のため指定できません。
- 投入するロットは**ロット番号**で指します。自動採番のロットは取り込むまで番号が分からないので、
  後で投入するロットは受入CSVで番号を指定してください。
- 日時は `yyyy-MM-dd HH:mm`（工場の時刻）で書きます。`+09:00` のようなオフセット付きでも構いません。
  生産実績は**開始日時で直を決める**ので、夜勤の実績は夜勤の時間帯に入る時刻にしてください。
- 実行記録（段取り〜製造条件データ）の**記録者は取り込んだユーザー**になります。
  CSVで別の作業者の名前を書く列はありません（他人の名義で実績を作れないようにするため）。
- 部材はバックフラッシュ（`Backflush=true`）でも消費できますが、予定材料に代替部品があると
  主材料と代替部品の両方が消費されます。代替部品を持つ品目は投入CSVで明示的に投入してください。
