依頼: $ARGUMENTS

`Orchestration.md` §4.1 のタスクカードを作る。**実装はしない。カードを出力して止まる。**

## 手順（この順序・この予算を守る）

1. `docs-dev/CodeMap.md` を読み、該当する業務行から対象ファイルを特定する。**まずここだけで済ませる。**
2. CodeMap で足りない場合のみ Grep（`-n`・パス限定、**最大4回**）で補う。ファイルは開かない、パスの確定だけでよい。
3. 関連する仕様は `Spec.md` を grep して節番号を特定する（全文を読まない）。業務Noは CodeMap の該当行から取る。
4. `src/MesApp.Infrastructure/Migrations/**` は参照しない。

## 出力

```
## タスク: <ID> <一行要約>
- 目的 / 背景:
- 変更対象: <確定したファイルパス。未確定は「調査で確定：<調査範囲>」と明記>
- 変更禁止: <既存API契約 / Migrations / 触ってはいけない領域>
- 受入条件(DoD): <機械的に検証できる形で。ビルド・テスト以外の固有条件を書く>
- 参照: Spec.md §x.y / MES.md No.X-XX-XX-XX / docs-dev/CodeMap.md の該当行
- 想定層: L1（設計判断あり） / L2（仕様確定済の実装） / L3（機械的）
- 想定変更ファイル数: N
```

## 自己チェック（出力の最後に1行で）

- 変更対象が3ファイルを超える、または「調査で確定」が2項目以上 → **粒度が粗い。分割案を併記する。**
- 認証／在庫更新／実績・原価計算／CSV取込／データモデル変更を含む → 想定層は L1 とし、その理由を書く。
